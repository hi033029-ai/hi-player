# Background blocker filter updates

- WorkManager persists unique daily work and a one-time stale check scheduled at app launch. Runs when connected and battery is not low; retries transient failures with exponential backoff (bounded retries per run). Android controls execution time; Doze, force-stop and OEM battery restrictions may delay it. First launch of this version is required to register work.
- Rules older than 24 hours (or with a different source version) refresh; opening the browser no longer needs to perform a synchronous network refresh. Downloads remain off the UI thread. Disabled ad blocking stays disabled and automatic work does not download while it is off. Re-enabling takes effect immediately with the last installed/bundled rules; the next scheduled check refreshes if stale.
- Updates contain declarative EasyList, EasyPrivacy and Peter Lowe filter rules, not remotely executed JavaScript. HTTPS approved-host checks apply to every redirect. Byte/time/line limits (including a per-source download deadline) and header/rule-count/content checks reject empty/HTML/error responses.
- Bundled protection is prepended, so automatic updates do not discard shipped YouTube rules. Downloads are staged; AtomicFile preserves/recovers the last installed filter file if replacement is interrupted. Manual and automatic installs are serialized. Failure retains working rules; nothing clears cookies or restarts a page.
- Successful installation reloads native filtering in process for subsequent requests. Existing page CSS is refreshed by the existing navigation/reload injection path; it is not retroactively rewritten by the worker. Existing blocked/loaded resources are not undone.
- No zero-ads guarantee: unsupported rules, changing site markup and unidentifiable server-stitched ads can escape. Bundled YouTube executable skipper changes still require an app update; this feature does not claim remote JavaScript updates.
